I recently decided to start writing about my projects. Instead of hand-writing raw HTML or relying on server-side tools like PHP or PostgreSQL, I wanted something simple and completely static.

<br>

After looking at existing static site generators, I decided to build my own. Basalt is a lightweight, single-binary static site generator written in C++. In fact, this website is written using it. The source code of the project is available on [GitHub](https://github.com/Vardan2009/basalt).

## About choosing C++

I selected C++ for this project for multiple reasons. First and foremost, I wanted it to be extremely portable and lightweight (just one executable file). This will greatly simplify the tool's installation and integration into CI systems. Second, I am more comfortable writing C++ than other languages for this purpose, such as Go or Rust.

## Design

Projects in basalt are directories containing a `basalt.yml` configuration file, which contains project information: paths and global website data. Here is an example of a configuration file:

```md
site:
  pages: src
  out: dist

  layouts: layouts
  partials: partials
  public: public

  data:
    website-title: My website
    year: 2026
    my-link: https://github.com/Vardan2009/basalt

```

### This is what each entry means:

- `pages`: The root directory of all pages in the website.
- `out`: The directory to generate the final static website to.
- `layouts`: The layouts directory contains all HTML files describing each page's general layout.
- `public`: Anything here will be directly copied to the output directory. It can be used for media and CSS files.
- `partials`: The directory which contains all partials (explained below)
- `data`: Globally-defined data

### Pages
Pages are written using Markdown and include a required YAML front matter for metadata.

```
---
title: Posts
date: 2026-02-24

layout: generic
---

# {{ title }} ({{ date }})
---

This is an example page.

```

The only required entry in the metadata is the `layout`, which selects the layout to use for that page.

### Layouts

As described above, layouts are modular and define the general layout of multiple pages by using special tags (prefixed with `basalt-...`) that evaluate to different pages. Here's an example:

```html
<!doctype html>
<html>

<head>
    <meta charset="utf-8" />
    <title>{{ title }} -- {{ website-title }}</title>
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <link rel="stylesheet" href="/style.css" />
</head>

<body>
    <basalt-partial>header</basalt-partial>

    <div id="content-container">
        <div class="content">
            <basalt-content />
        </div>
    </div>

    <basalt-partial>footer</basalt-partial>
</body>

</html>

```

`basalt-content` is a special tag that evaluates to the actual text (converted from Markdown to HTML) written in the pages. Variables (like `{{ title }}`) are resolved using a custom templating engine.

### Partials

Partials are modular pieces of HTML that are intended to be reused throughout multiple pages. Included using the `basalt-partial` tag, they're very convenient for things like headers and footers.

## Implementation

I used multiple libraries for parsing Markdown, HTML and YAML sources. The program reads the config file, identifies and parses all used files, generates an HTML file for each page by recursively walking and modifying the HTML syntax tree.
